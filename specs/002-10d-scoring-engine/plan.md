# Implementation Plan: 10-Dimension Scoring Engine (F9)

**Branch**: `002-10d-scoring-engine` | **Date**: 2026-05-02 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/002-10d-scoring-engine/spec.md`

## Summary

Every discovered job (with populated `jd_raw`) is automatically scored by the Python LangGraph agent across 10 structured dimensions using LiteLLM. Gate-pass dimensions are evaluated first — failing either auto-grades the job F with no further processing. The 8 weighted dimensions produce a numeric score (1.0–5.0) mapped to an A–F grade. For B+ jobs, a 6-block markdown report is generated. All results are written to new columns on the `jobs` table immediately after each job scores. A HITL review dashboard on `/applications` surfaces scored (non-F) jobs for candidate approval/rejection/snooze. Grade filter preference persists to `candidates.preferences`.

## Technical Context

**Language/Version**: Python 3.14 (agent), TypeScript 5 + Node.js 22 (Next.js)
**Primary Dependencies**: LiteLLM `^1.40`, Pydantic 2.x, LangGraph `^1.0`, aiosqlite `^0.22` (dev), asyncpg `^0.31` (prod), Next.js 15, Drizzle ORM, Tailwind CSS v4, shadcn/ui
**Storage**: Neon PostgreSQL (production), SQLite `proxim-dev.db` (local dev via `DATABASE_URL`)
**Testing**: pytest + pytest-asyncio (Python), Vitest + @testing-library/react (Next.js)
**Target Platform**: Python polling daemon + Next.js 15 App Router
**Project Type**: Dual-runtime web application (Python agent + Next.js)
**Performance Goals**: Single-job scoring completes end-to-end within 45 seconds (SC-002)
**Constraints**: F-grade jobs must never appear on dashboard (SC-004); zero fabricated proof points in CV Match tables (SC-003)
**Scale/Scope**: Single candidate, ~100–500 jobs per pipeline run

**Structure Decision**: Dual-runtime following established patterns. Python agent handles all LLM calls and scoring logic (per Constitution §V, §VII). ## Complexity Tracking

No constitution violations. Scoring in Python (not Next.js) is required by Constitution §V (LiteLLM for Python agent) and §VII (Python service owns multi-step pipeline). The self-repair retry loop (FR-008) is a single `for` loop with max 2 iterations — no additional infrastructure.
