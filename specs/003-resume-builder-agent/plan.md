# Implementation Plan: Resume Builder Agent (F10)

**Branch**: `003-resume-builder-agent` | **Date**: 2026-05-03 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/003-resume-builder-agent/spec.md`

## Summary

After a candidate approves a job from the HITL dashboard, the Python LangGraph Resume Builder agent automatically generates an archetype-personalised resume and a one-page cover letter, both rendered as ATS-safe PDFs via WeasyPrint from Jinja2/HTML templates. Personalisation reorders and reframes existing proof points per one of 5 detected archetypes — it never fabricates credentials. Keywords (15–20) are extracted from the JD via LiteLLM structured output and injected naturally into the resume. A self-review coherence loop (max 2 retries) validates injected text before finalisation. Every generated PDF pair is stored as an immutable version record linked to the job, archetype, and base CV hash. Submitted resumes are locked — regeneration creates a new version rather than overwriting. Next.js reads version records and serves PDFs; all LLM calls and rendering run in the Python daemon.

## Technical Context

**Language/Version**: Python 3.14 (agent), TypeScript 5 + Node.js 22 (Next.js)
**Primary Dependencies**: LiteLLM `^1.40`, Pydantic `^2.7`, LangGraph `^0.4`, WeasyPrint `^62`, Jinja2 `^3.1`, asyncpg `^0.29` (prod), aiosqlite `^0.22` (dev), Next.js 15, Drizzle ORM, Tailwind CSS v4, shadcn/ui
**Storage**: Neon PostgreSQL (prod) / SQLite (dev) — new `resume_versions` table; PDF files stored on local disk (path stored in DB), configurable to object storage
**Testing**: pytest + pytest-asyncio (Python agent), Vitest + @testing-library/react (Next.js)
**Target Platform**: Python polling daemon + Next.js 15 App Router
**Project Type**: Dual-runtime web application (Python agent + Next.js)
**Performance Goals**: Full PDF pair (resume + cover letter) generated within 60 seconds per job (FR-013, SC-004)
**Constraints**: Zero fabricated proof points (III. Factual Integrity); Aptos font self-hosted — no external CDN; ATS text extraction ≥ 85% (SC-003); submitted versions immutable (FR-011)
**Scale/Scope**: Single candidate, ~50–200 approved jobs per run

**Structure Decision**: Dual-runtime following established patterns. Python agent owns all LLM calls, PDF rendering, and version writes (Constitution §V, §VII). Next.js exposes trigger and download routes only; never calls Python directly. Resume builder graph follows the pattern established by `graphs/scoring.py` — sequential nodes, per-job progress to `pipeline_logs`, self-repair retry via conditional edges.

## Complexity Tracking

No constitution violations. PDF rendering in Python (not Next.js) is required by Constitution §VII (Python service owns multi-step pipeline). WeasyPrint introduces an OS dependency (libpango, libcairo) in the Python agent environment; this is scoped entirely to the agent's Docker/Poetry environment and does not affect the Next.js runtime.
