## 1. Modifications to `pipeline_runs` Table

Four denormalised aggregate columns added, populated by the Python agent at run completion.

### Drizzle Schema addition (`src/db/schema.ts`)

```typescript
export const pipelineRuns = pgTable('pipeline_runs', {
  // ... existing columns ...
  // F7 aggregate fields (populated at run completion by Python agent)
  abGradeCount:     integer().default(0).notNull(),   // jobs with grade A or B in this run
  resumesGenerated: integer().default(0).notNull(),   // resume_versions rows for jobs in this run
  emailsSent:       integer().default(0).notNull(),   // email_drafts rows with status='sent'
  repliesReceived:  integer().default(0).notNull(),   // email_cadences rows with reply_detected_at IS NOT NULL
})
```

### SQLite Schema addition (`src/db/schema.sqlite.ts`)

```typescript
// Same column names, same defaults, integer type works for both drivers.
abGradeCount:     integer().default(0).notNull(),
resumesGenerated: integer().default(0).notNull(),
emailsSent:       integer().default(0).notNull(),
repliesReceived:  integer().default(0).notNull(),
```

### Python agent population query (`agent/agent/db.py`)

```python
async def update_run_aggregates(conn, run_id: str, candidate_id: str) -> None:
    """Called once when pipeline_runs.status transitions to 'completed'."""
    await conn.execute("""
        UPDATE pipeline_runs SET
          ab_grade_count = (
            SELECT COUNT(*) FROM jobs
            WHERE pipeline_run_id = $1 AND grade IN ('A','B')
          ),
          resumes_generated = (
            SELECT COUNT(*) FROM resume_versions rv
            JOIN jobs j ON j.id = rv.job_id
            WHERE j.pipeline_run_id = $1
          ),
          emails_sent = (
            SELECT COUNT(*) FROM email_drafts ed
            JOIN email_cadences ec ON ec.id = ed.cadence_id
            JOIN jobs j ON j.id = ec.job_id
            WHERE j.pipeline_run_id = $1 AND ed.status = 'sent'
          ),
          replies_received = (
            SELECT COUNT(*) FROM email_cadences ec
            JOIN jobs j ON j.id = ec.job_id
            WHERE j.pipeline_run_id = $1 AND ec.reply_detected_at IS NOT NULL
          )
        WHERE id = $1
    """, run_id)
```

## 5. State Transitions

### Interview callback (new action)

```
jobs.status: approved | resume_ready | submitted
    │
    ▼ (candidate clicks "Mark as Interview")
jobs.interviewCallbackAt = now()   (jobs.status unchanged)
    │
    ▼ (candidate clicks again — "Unmark" — out of scope for MVP)
```

The "Mark as Interview" action does NOT change `jobs.status`. It records an outcome alongside the existing processing pipeline.

### Failed job retry

```
pipeline_jobs.status: failed
    │
    ▼ POST /api/jobs/[jobId]/retry
      → INSERT pipeline_jobs (job_type = <same type as failed job>, status='queued')
      → jobs.status reset to 'approved' (ready for resume_builder re-pickup)
         OR 'resume_ready' if retry is for linkedin_connector/outreach_mailer
    │
    ▼ Python daemon picks up new pipeline_jobs row → restarts the stage
```

## 6. Aggregate Metric Computation (query-time, analytics route)

For a given `candidateId` and `timeRange`, the analytics endpoint computes:

```typescript
// Completed runs in time range
const runs = await db
  .select()
  .from(pipelineRuns)
  .where(
    and(
      eq(pipelineRuns.candidateId, candidateId),
      eq(pipelineRuns.status, 'completed'),
      timeRange !== 'all'
        ? gte(pipelineRuns.startedAt, startOfRange)
        : undefined,
    )
  )

// Grade rate: sum(abGradeCount) / sum(jobsDiscovered)
const abGradeRate = totalJobs > 0
  ? Math.round((sumAbGrade / totalJobs) * 100)
  : 0

// Email open rate: count(openDetectedAt IS NOT NULL) / count(sent drafts)
// Email reply rate: count(replyDetectedAt IS NOT NULL) / count(sent cadences)

// Interview callback rate: count(interviewCallbackAt IS NOT NULL) / count(approved jobs)
// All rates computed via separate aggregate queries joining relevant tables.
```

## 7. Run History Pagination

Run history is paginated at 50 rows per page (FR-010). Query:

```sql
SELECT id, status, started_at, completed_at,
       jobs_discovered, ab_grade_count, resumes_generated,
       emails_sent, replies_received
FROM pipeline_runs
WHERE candidate_id = $1
  AND (status = 'completed' OR status = 'failed')
  [AND started_at >= $timeRangeStart]
ORDER BY started_at DESC
LIMIT 50 OFFSET ($page - 1) * 50
```

The route returns `{ runs, total, page, totalPages }`.

## 9. CSV Export Schema

One CSV row per completed `pipeline_run`. Header + data rows:

```
run_id,started_at,completed_at,duration_minutes,jobs_discovered,ab_grade_count,
resumes_generated,emails_sent,replies_received,status
```

Empty fields use empty string (not `null`). Timestamps in ISO 8601. Duration in whole minutes (rounded down). In-progress runs excluded from export.
